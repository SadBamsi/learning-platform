## Задания на закрепление

Файлы сохраняйте как `.mjs`.

### Задание 1. Куда уйдёт ошибка?

Для каждого фрагмента определите: поймает ли её `catch`? Если нет, что произойдёт с процессом?

```js
// A
try { setTimeout(() => { throw new Error("A"); }, 0); } catch (e) { console.log("caught A"); }

// B
try { Promise.reject(new Error("B")); } catch (e) { console.log("caught B"); }

// C
try { await Promise.reject(new Error("C")); } catch (e) { console.log("caught C"); }

// D
async function f() { throw new Error("D"); }
try { f(); } catch (e) { console.log("caught D"); }
```

### Задание 2. Иерархия ошибок

Реализуйте `AppError`, `NotFoundError` и `ValidationError` (поля `status`, `code`, `expose`, `cause`). Напишите функцию `toHttp(err)`, возвращающую `{ status, body }`: для известных ошибок — их данные, для неизвестных — `500` и безопасное сообщение без деталей.

### Задание 3. Error middleware

Напишите на `node:http` (без фреймворка) мини-обёртку `handle(fn)`, которая вызывает async-обработчик и любую ошибку переводит в JSON-ответ через `toHttp`. Проверьте на маршрутах: успешный, `NotFoundError`, неожиданное исключение.

### Задание 4. Graceful shutdown

Напишите HTTP-сервер с маршрутом `/slow` (отвечает через 5 секунд). Реализуйте корректную остановку по `SIGTERM`/`SIGINT`: перестать принимать новые соединения, дождаться `/slow`, затем выйти с кодом 0. Добавьте страховочный таймаут 10 секунд. Проверьте: запустите `curl localhost:3000/slow`, в другом терминале отправьте `kill -TERM <pid>`; ответ должен прийти полностью, а новый запрос — получить отказ в соединении.

### Задание 5. Глобальные обработчики

Добавьте `unhandledRejection` и `uncaughtException`, которые логируют ошибку и завершают процесс с кодом 1. Проверьте, какой код завершения вернёт процесс (`echo $?`), если: (а) бросить исключение в `setTimeout`; (б) оставить отклонённый промис без обработчика; (в) добавить обработчик `uncaughtException`, который только логирует и ничего больше не делает.

### Задание 6. Ретраи только для операционных ошибок

Напишите функцию `withRetry(fn, { retries, isRetryable })`. Повторяйте вызов только для операционных ошибок (например, `ECONNRESET`, `ETIMEDOUT`, HTTP 503), но **не** для программных ошибок (`TypeError`) и клиентских 4xx.

### Задание 7. Ответ для интервью

За 2 минуты расскажите: *«Как вы обеспечиваете, чтобы деплой нового релиза не приводил к потерянным запросам?»* В ответе: SIGTERM, readiness, `server.close`, закрытие ресурсов, таймаут, rolling update, `terminationGracePeriodSeconds`.
