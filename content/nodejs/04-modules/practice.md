## Задания на закрепление

Создавайте папку для каждого задания и запускайте через `node`.

### Задание 1. `exports` против `module.exports`

Что выведет `app.js` для каждого из трёх вариантов `lib.js`? Объясните.

```js
// Вариант A
exports.x = 1;

// Вариант B
exports = { x: 1 };

// Вариант C
module.exports = { x: 1 };
exports.y = 2;
```

```js
// app.js
console.log(require("./lib"));
```

### Задание 2. Кэширование

Создайте `counter.js`, который при загрузке печатает `"loaded"` и экспортирует функцию `inc()`, увеличивающую внутренний счётчик. Подключите его из `a.js` и `b.js`, затем оба из `main.js`. Сколько раз выведется `loaded`? Разделяют ли `a` и `b` один и тот же счётчик? Проверьте `require.cache`.

### Задание 3. Циклическая зависимость

Воспроизведите цикл `a.js ↔ b.js` в CommonJS. Покажите, что один из модулей видит неполный экспорт. Затем исправьте двумя способами: (1) ленивый `require` внутри функции, (2) выделение общего кода в `shared.js`.

### Задание 4. Миграция на ESM

Переведите проект из задания 2 на ES Modules:

1. добавьте `"type": "module"` в `package.json`;
2. замените `require`/`module.exports` на `import`/`export`;
3. выведите путь к текущему файлу и каталогу без `__dirname`/`__filename`;
4. загрузите `data.json` через `import ... with { type: "json" }`.

### Задание 5. Live bindings

Проверьте различие между CJS и ESM на примере счётчика: экспортируйте `count` и функцию `inc()`. Выведите `count` до и после `inc()` в CJS и в ESM. Что изменится и почему?

### Задание 6. Interop

1. Из ESM-файла импортируйте CJS-модуль с `module.exports = { a: 1, b: 2 }` двумя способами: `import x from` и `import { a } from`. Что получится?
2. Из CJS-файла загрузите ESM-модуль, используя динамический `import()`.
3. Проверьте, работает ли у вас `require()` для синхронного ESM-модуля на вашей версии Node (`node --version`).

### Задание 7. Ответ для интервью

За 1 минуту объясните вслух: *«Почему в ESM нужно писать расширения файлов, а в CommonJS не нужно, и какие преимущества даёт статичность `import`?»*
