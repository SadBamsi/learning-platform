## Задания на закрепление

Если не указано иное, выполняйте на чистом `node:http` без фреймворков: так вы поймёте механику. Файлы — `.mjs`.

### Задание 1. Статус-коды

Подберите самый подходящий статус для каждой ситуации:

1. Клиент прислал битый JSON.
2. Клиент не передал токен.
3. Токен валиден, но пользователь пытается удалить чужой заказ.
4. Создан новый заказ.
5. Попытка зарегистрироваться с email, который уже существует.
6. Поле `age` = `-5` не прошло валидацию (JSON корректен).
7. Клиент превысил лимит запросов.
8. Удаление выполнено, тело ответа не нужно.
9. База данных недоступна.
10. Ресурс не менялся с момента `If-None-Match`.

### Задание 2. Идемпотентность

Для каждого запроса скажите, идемпотентен ли он, и что случится при повторе: `GET /orders/1`; `PUT /users/1 {name:"A"}`; `POST /orders {…}`; `DELETE /orders/1`; `PATCH /counter {inc: 1}`. Как сделать `POST /orders` безопасным для повтора?

### Задание 3. Свой `compose`

Реализуйте `compose(middlewares)` (как в теории) и мини-«фреймворк» на `node:http`: `app.use(fn)`, `app.listen(port)`. Подключите три middleware: логирование времени, парсер JSON-тела, обработчик «404». Проверьте, что вызов `next()` дважды вызывает ошибку.

### Задание 4. REST для задач (todo)

Спроектируйте и реализуйте in-memory API на `node:http`:

- `GET /todos?done=true&limit=10&after=<id>` — список с фильтром и cursor-пагинацией;
- `POST /todos` — создание (валидация: `title` — непустая строка до 200 символов) → `201` + `Location`;
- `GET /todos/:id`, `PATCH /todos/:id`, `DELETE /todos/:id` (`204`);
- единый формат ошибок `{ "error": { "code", "message" } }`;
- `404` для неизвестного маршрута и `405` для неподдерживаемого метода.

### Задание 5. Условные запросы

Добавьте в `GET /todos/:id` заголовок `ETag` (хеш тела ответа) и поддержку `If-None-Match`: при совпадении ответьте `304` без тела. Проверьте через `curl -i` с заголовком.

### Задание 6. Cursor против offset

Есть таблица из 10 млн строк. Сравните запросы `SELECT … ORDER BY id LIMIT 20 OFFSET 5000000` и `SELECT … WHERE id > 5000000 ORDER BY id LIMIT 20`. Какой быстрее и почему? Какие недостатки у второго? Как реализовать курсор для сортировки по `created_at` с неуникальными значениями?
