## Задания на закрепление

Файлы сохраняйте как `.mjs`.

### Задание 1. Вынести CPU-нагрузку в воркер

Сервер на `node:http` имеет маршрут `/fib?n=40`, который считает число Фибоначчи рекурсивно. Сначала сделайте его синхронным и покажите, что параллельный запрос `/ping` «зависает». Затем перенесите вычисление в `worker_threads` и убедитесь, что `/ping` отвечает мгновенно.

### Задание 2. Пул воркеров

Реализуйте простой пул из N воркеров с очередью задач: метод `pool.run(data)` возвращает промис; свободный воркер берёт следующую задачу из очереди. Проверьте на 20 задачах с пулом из 4 воркеров. Почему пул лучше, чем `new Worker` на каждую задачу?

### Задание 3. Общая память

Создайте `SharedArrayBuffer` на 4 байта. Запустите 4 воркера, каждый из которых 100 000 раз увеличивает общий счётчик: сначала обычным `view[0]++`, затем `Atomics.add`. Сравните итог с ожидаемым 400 000 и объясните разницу.

### Задание 4. cluster

Запустите HTTP-сервер через `cluster`, число воркеров равно `os.availableParallelism()`. Сделайте так, чтобы падение воркера (эмулируйте маршрутом `/crash`, вызывающим `process.exit(1)`) приводило к запуску нового. Выполните 20 запросов `curl` и посмотрите, какие PID отвечают.

### Задание 5. Безопасный запуск внешней команды

Дан небезопасный код:

```js
import { exec } from "node:child_process";
app.get("/ping", (req, res) => {
  exec(`ping -c 1 ${req.query.host}`, (err, out) => res.send(out));
});
```

Покажите, какой `host` приведёт к выполнению постороннего кода, и перепишите безопасно.

### Задание 6. Stateless или нет?

Сервис хранит корзину пользователя в `const carts = new Map()`, а загруженные картинки пишет в `./uploads`. Он запущен в трёх подах за балансировщиком. Какие проблемы возникнут? Что нужно изменить, чтобы сервис стал stateless?

### Задание 7. Ответ для интервью

Объясните за 2 минуты: *«У нас API на Node.js уткнулся в CPU. Как диагностировать и что делать?»* В ответе: профилирование (event loop lag, CPU profile), выделение CPU-bound участков, воркеры/очередь, горизонтальное масштабирование.
