> **Ответ за 30 секунд.** `useRef(initial)` возвращает **один и тот же объект** `{ current }` на протяжении всей жизни компонента. Изменение `ref.current` **не вызывает рендер** — этим `ref` отличается от `state`. Два основных применения: (1) **доступ к DOM-узлу** (`<input ref={ref} />` — после монтирования `ref.current` указывает на элемент: фокус, прокрутка, измерения, интеграция со сторонними библиотеками); (2) **изменяемое значение «вне рендера»**: id таймера, предыдущее значение, актуальный колбэк, флаг. `ref.current` нельзя читать и менять **во время рендера** (кроме ленивой инициализации): рендер должен быть чистым. В React 19 `ref` передаётся в функциональный компонент **как обычный проп**, поэтому `forwardRef` для новых компонентов не нужен; `useImperativeHandle` позволяет открыть родителю не весь узел, а **узкий API** (`focus`, `clear`).

## Что именно спрашивают

- «Чем `useRef` отличается от `useState`? Когда что использовать?»
- «Как получить доступ к DOM-элементу? Когда `ref.current` не `null`?»
- «Что такое `forwardRef`? Что изменилось в React 19?»
- «Зачем нужен `useImperativeHandle`?»
- «Как хранить id таймера / предыдущее значение пропса?»
- «Что такое callback ref и чем он отличается от объекта ref?»
- «Можно ли читать/писать `ref.current` в рендере?»

## ref против state

| | `useState` | `useRef` |
|---|---|---|
| Сохраняется между рендерами | да | да |
| Изменение вызывает рендер | **да** | **нет** |
| Читать/менять в рендере | читать — да | **нельзя** (кроме инициализации) |
| Обновление | асинхронное (в следующем рендере) | немедленное (`ref.current = x`) |

Проверено: два клика по кнопке, меняющей `ref.current`, дали **0** рендеров, а текст на экране остался `0`, хотя в `ref` уже `2`. Поэтому **всё, что влияет на экран, должно быть в `state`**, а `ref` — для данных, которые интерфейсу «не важны»: id таймера, ссылка на DOM-узел, предыдущее значение, кэш, флаги.

## Доступ к DOM

```jsx
function Form() {
  const inputRef = useRef(null);

  useEffect(() => {
    inputRef.current.focus();           // после монтирования ref заполнен
  }, []);

  return <input ref={inputRef} />;
}
```

Порядок (проверено): во время **первого рендера** `ref.current === null` (DOM ещё нет); React присваивает узел на фазе commit, поэтому читать его нужно в **обработчиках событий и эффектах**, а не в теле компонента. При размонтировании `ref.current` снова становится `null`.

Типичные применения: фокус, прокрутка (`scrollIntoView`), воспроизведение `<video>`, измерение размеров (`getBoundingClientRect`), интеграция сторонних библиотек (карты, графики, редакторы). Для измерений до отрисовки кадра используют `useLayoutEffect` (проверено порядок вызовов: `render h=0` → `layout setH` → `render h=123`; то, что браузер не успевает показать промежуточный кадр, следует из документации и в jsdom, где нет отрисовки, не проверялось).

React управляет DOM сам. **Не изменяйте через `ref` то, чем управляет React** (текст, дочерние узлы, классы, которые рендерит React) — React не знает об этих изменениях, и они могут «потеряться» или сломать сверку. Безопасно: `focus()`, `scrollIntoView()`, `measure`, вызов императивных API.

## Хранение значений «вне рендера»

```jsx
// id таймера
const timerId = useRef(null);
function start() { timerId.current = setInterval(tick, 1000); }
function stop() { clearInterval(timerId.current); timerId.current = null; }
useEffect(() => () => clearInterval(timerId.current), []);   // очистка при размонтировании

// предыдущее значение
function usePrevious(value) {
  const ref = useRef();
  useEffect(() => { ref.current = value; });   // обновляется ПОСЛЕ рендера
  return ref.current;                           // поэтому во время рендера — прошлое значение
}
```

Секундомер на `ref` проверен запуском: повторный клик «start» не создаёт второй интервал, после «stop» значение не меняется. `usePrevious` возвращает значение предыдущего рендера (проверено: при смене `1 → 2` показано `1`).

Также `ref` используют для хранения «актуальной версии колбэка» (паттерн из темы про хуки) и для флага «компонент смонтирован».

## Чего нельзя: ref в рендере

Чтение и запись `ref.current` в теле компонента делают результат зависимым от количества вызовов рендера. Проверено: компонент делает `r.current += 1` в теле и показывает значение; в `StrictMode` (рендер вызывается дважды) уже при первом рендере показано **2**. Допустима единственная форма — **ленивая инициализация**:

```jsx
const ref = useRef(null);
if (ref.current === null) ref.current = new ExpensiveThing();   // допустимо
```

## Передача ref в дочерний компонент

**React 19:** `ref` — обычный проп функционального компонента.

```jsx
function MyInput({ ref, ...props }) {
  return <input ref={ref} {...props} />;
}

function Form() {
  const r = useRef(null);
  useEffect(() => { r.current.focus(); }, []);
  return <MyInput ref={r} />;
}
```

Проверено: работает без `forwardRef` и без предупреждений.

**До React 19** (и в существующем коде): нужно `forwardRef`:

```jsx
const MyInput = forwardRef(function MyInput(props, ref) {
  return <input ref={ref} {...props} />;
});
```

Проверено: на React 19 `forwardRef` по-прежнему работает. Для новых компонентов он не нужен.

## useImperativeHandle: узкий API вместо всего DOM

По умолчанию родитель получает **весь** DOM-узел и может делать с ним что угодно. `useImperativeHandle` позволяет открыть только нужные методы:

```jsx
function Field({ ref }) {
  const inner = useRef(null);
  useImperativeHandle(ref, () => ({
    focus: () => inner.current.focus(),
    clear: () => { inner.current.value = ""; },
  }), []);
  return <input ref={inner} defaultValue="abc" />;
}

// родитель видит только { focus, clear }
```

Проверено: `Object.keys(ref.current)` → `['focus', 'clear']`. Применяют для компонентов-библиотек (модалки с `open()`/`close()`, видеоплееры с `play()`/`pause()`). Но императивное управление — запасной вариант: если можно выразить через `props`/`state` (`<Modal open={isOpen} />`), так и делайте.

## Callback ref

Вместо объекта в `ref` можно передать **функцию**: React вызывает её с элементом при монтировании и с `null` при размонтировании. Это удобно, когда нужно выполнить действие в момент появления узла (в том числе у динамических списков).

В React 19 callback ref может **вернуть cleanup-функцию** (она вызывается вместо `ref(null)`):

```jsx
const ref = useCallback((el) => {
  if (!el) return;
  const ro = new ResizeObserver(([e]) => setWidth(e.contentRect.width));
  ro.observe(el);
  return () => ro.disconnect();     // вызывается при размонтировании узла
}, []);
```

Проверено (с заглушкой `ResizeObserver`): ширина обновляется, при размонтировании вызван `disconnect`, наблюдатель создан один раз.

**Важно:** если передать в `ref` новую функцию на каждом рендере (инлайн), React каждый раз вызывает старую с `null` и новую с элементом. Проверено: инлайн-функция даёт при рендере `[null, attach]`, `useCallback` — ничего. Для дорогих действий мемоизируйте callback ref.

Для списков узлов: `ref` в цикле нельзя вызывать через `useRef` по числу элементов (правила хуков). Используйте callback ref, который складывает узлы в `Map`/массив в `ref`.

## Частые follow-up вопросы

**Почему `ref.current` равен `null` в теле компонента при первом рендере?**
DOM-узел создаётся и присваивается в фазе commit, после рендера.

**Когда лучше `state`, когда `ref`?**
Если значение влияет на то, что видит пользователь, — `state`. Если это служебное значение (таймер, предыдущее, DOM-узел) — `ref`.

**Можно ли использовать `ref` в зависимостях эффекта?**
`ref`-объект стабилен, добавлять его не нужно (линтер знает). А вот `ref.current` в зависимости не кладут: изменение не вызывает рендер, эффект не заметит.

**Как передать `ref` к компоненту, обёрнутому в `memo`?**
В React 19 — как обычный проп. Раньше `memo(forwardRef(...))`.

**Что такое «escape hatch»?**
`ref` — один из способов выйти за пределы декларативной модели React к императивным API браузера. Использовать его нужно минимально.

**Как получить размеры элемента?**
`getBoundingClientRect()` в `useLayoutEffect` или `ResizeObserver` через callback ref.

## Типичные ошибки

- Хранить в `ref` то, что должно влиять на отображение.
- Читать/писать `ref.current` в рендере.
- Менять через `ref` DOM, которым управляет React.
- Ожидать, что `ref.current` заполнен до монтирования.
- Класть `ref.current` в массив зависимостей.
- Забывать очищать таймеры/наблюдатели, id которых хранятся в `ref`.
- Открывать родителю весь DOM-узел там, где достаточно узкого API через `useImperativeHandle`.
